Is your NEAR account quantum-safe?

Type any NEAR account. This reads its access keys from the public blockchain and tells you whether they would survive a large quantum computer, and how to upgrade if not.

Try: vault.bazaar-sovereign-2026.testnetroot.near

Adding a quantum-safe key is step one. While a classic full-access key stays on the account, that old key can still move everything.

How to upgrade (near-cli-rs 0.31+)

Try it on testnet first. Replace you.testnet with your account.

1 · Add a quantum-safe key (your current key approves it)
near account add-key you.testnet grant-full-access autogenerate-new-keypair --signature-scheme ml-dsa-65 save-to-legacy-keychain network-config testnet sign-with-legacy-keychain send
2 · Sign something with the new key
near tokens you.testnet send-near you.testnet '0.001 NEAR' network-config testnet sign-with-access-key-file ~/.near-credentials/testnet/you.testnet/ml-dsa-65-hash_<…>.json send
3 · Delete the old classic key, signed by the new one
near account delete-keys you.testnet public-keys ed25519:<old key> network-config testnet sign-with-access-key-file ~/.near-credentials/testnet/you.testnet/ml-dsa-65-hash_<…>.json send

Not every wallet or dapp supports post-quantum keys yet (Meteor Wallet does). Keep a backup of the new key file before you delete anything.

Good to know

  • ML-DSA-65The NIST post-quantum signature standard (FIPS 204, also called Dilithium). Live for NEAR accounts since Q2 2026 (NEP-645).
  • SizeA signature is 3,309 bytes instead of 64. The chain stores only a 32-byte hash of the 1,952-byte public key, so storage costs stay the same.
  • Still to comeValidators still sign blocks with classic keys; post-quantum consensus is targeted for the end of 2027. The MPC signing behind Chain Signatures has no post-quantum version yet.
